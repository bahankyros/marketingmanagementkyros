# Database Architecture

## Core Tables & Relationships

- `outlets`
  - Master outlet table.
  - Linked by `outlet_id` from outlet-scoped records such as `users`, `events`, `tasks`, `mascot_bookings`, `sales`, and `financials`.
- `users`
  - Application profile table linked to Supabase Auth through `auth_user_id`.
  - Stores `role`, `outlet_id`, `outlet_name`, and `status`.
  - `role` is constrained to `admin`, `supervisor`, `finance`, or `pic`.
- `events`
  - Calendar/event table.
  - May link to `outlets` through `outlet_id`, to `campaigns` through `campaign_id`, and to the submitter through `submitter_user_id`.
- `event_history_logs`
  - Audit trail for event creation and updates.
  - Links to `events` through `event_id`.
  - Links to the acting app user through `actor_user_id`.
- `tasks`
  - Operational work/request table.
  - Links to `outlets` through `outlet_id`.
  - Links to creator and assignee profiles through `assigned_by_user_id` and `assigned_to_user_id`.
  - Optionally links to `events` through `event_id`.
- `notifications`
  - First-class notification table.
  - Links to the recipient app user through `recipient_user_id`.
  - Optionally links to an actor through `actor_user_id`.
  - References source records through `entity_type` and `entity_id`; currently supports `task` and `mascot_booking`.
- `mascot_bookings`
  - Mascot request and approval table.
  - Links to `outlets` through `outlet_id`.
  - Links to requester and approver profiles through `requested_by_user_id` and `approved_by_user_id`.

## RBAC Matrix

| Role | Payload Value | Primary Access Pattern |
| --- | --- | --- |
| Admin | `admin` | Full administrative access through admin RLS policies. |
| Supervisor | `supervisor` | Outlet-scoped access through `outlet_id`; can work only inside their assigned outlet. |
| Finance | `finance` | Finance/reporting-oriented role in the app; direct write access is still governed by table-specific RLS. |
| PIC | `pic` | Outlet-scoped access through `outlet_id`; can create outlet-bound requests and operate only inside their assigned outlet. |

Roles MUST be lowercase in all frontend payloads, SQL seed data, RPC inputs, and profile updates. The `users.role` check constraint accepts only `admin`, `supervisor`, `finance`, and `pic`; values such as `PIC`, `Admin`, or `Supervisor` will violate the schema contract.

## RLS Policy Summary

- RLS is enabled on the application tables and Supabase Storage objects.
- `public.current_app_user_id()` maps the authenticated Supabase user to `public.users.id`.
- `public.current_app_user_outlet_id()` resolves the authenticated user's assigned outlet.
- `public.is_admin()` grants broad access only when the current app profile role is `admin`.
- `public.owns_outlet(outlet_id)` is the main outlet-scope guard for PICs and supervisors.
- Admin policies generally allow full `select`, `insert`, `update`, and `delete` access on operational tables.
- PICs and supervisors can only see or write outlet-bound records tied to their own `outlet_id`, unless a table also allows access because they are the creator, assignee, requester, or approver.
- `events` allow admins full access; outlet users can select, insert, and update events tied to their own outlet or submitted by themselves.
- `event_history_logs` allow admins full access; non-admin users can read or insert logs only when they can access the linked event and the `actor_user_id` matches their own app user profile.
- `tasks` allow admins full access; outlet users can select and update tasks tied to their outlet, created by them, or assigned to them. Outlet users can insert tasks only for their own outlet and only when `assigned_by_user_id` is their own app user id.
- `notifications` allow admins full access; non-admin users can select only notifications where `recipient_user_id` is their own app user id.
- Notification rows are generated by trusted database functions and triggers such as `notify_task_changes()` and `notify_mascot_booking_changes()`.
- Private Storage buckets are scoped by helper policies for event proofs, task proofs, campaign assets, and mall display proofs. Access must match the linked record permissions rather than relying on public URLs.
